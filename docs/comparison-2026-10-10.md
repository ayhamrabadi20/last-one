## التغييرات المنفّذة

- إدارة حسابات من لوحة الأدمن: إيقاف، حظر، تفعيل، تغيير دور، إبطال جلسات، وحذف مع تأكيد البريد وحذف البيانات التابعة.
- حماية الأدمن الرئيسي والحساب الحالي وآخر مدير مفعّل؛ الدور الجديد لا يُقبل من التسجيل أو تعديل الملف الشخصي.
- سجل محاولة قبل التعديل ثم نتيجة اكتمال؛ عند فشل جزء من الحذف يبقى الحساب معطّلًا بدل منحه الوصول. الحذف متعدد المجموعات ليس transaction؛ رسالة الخطأ تطلب تحديث الحالة قبل إعادة المحاولة.
- فحص جلسات قاعدة البيانات لكل API محمي، وربط الجلسة بمعرّف الحساب حتى لا يرث حساب يعيد استخدام البريد جلسة الحساب المحذوف.
- مظهر نهاري/ليلي/حسب النظام في الهيدر وصفحات الدخول ولوحة الأدمن، محفوظ في الحساب.
- تحسين الانتظار وعدم بناء خطوات قانونية على تخمين النموذج.

## التحقق وحدوده

نجح 145 اختبارًا في 22 ملف Vitest، وفحص TypeScript وESLint، وبناء Next.js للإنتاج. أضيفت اختبارات رفض المستخدم العادي، حماية المدير، آخر مدير، تأكيد الحذف، حذف البيانات التابعة، إبطال الجلسات، الحظر، إصدار الجلسة، انقطاع قاعدة البيانات، صحة تفضيلات المظهر، ومنع افتراض الحقائق القانونية.

نجح اختبار HTTP على نسخة إنتاج وقاعدة MongoDB الفعلية: 28 تحققًا، تشمل التسجيل دون تصعيد الدور، حفظ المظهر، الحظر ومنع الدخول والجلسة المفتوحة، التفعيل دون استعادة التوكن القديم، ترقية وخفض الدور، حماية الرئيسي، حذف البيانات التابعة، إعادة تسجيل البريد دون توريث الجلسة، والخروج. نُظفت الحسابات والسجلات المؤقتة بعده. يمكن إعادة الاختبار باستخدام `node --env-file=.env.local scripts/verify-account-management.mjs` مع خادم اختبار على 3104 أو تحديد `VERIFY_BASE_URL`.

لا ننسب أرقام الاختبارات أو قياسات زمن النموذج والتباين المرفقة بالملف إلى مشروعنا. لم يُنفّذ تدقيق بصري شامل لكل شاشة أو اختبار حي لجودة Ollama في هذه الجولة. إيقاف الانتظار يوقف الطلب في المتصفح ويهمل نتيجته؛ لا يضمن إنهاء التوليد الجاري داخل Ollama أو إلغاء عملية حفظ بدأت في الخادم. معدل الطلبات الموجود في ذاكرة العملية يحتاج مخزنًا مشتركًا عند تشغيل عدة خوادم.
