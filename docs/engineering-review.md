# القرارات الهندسية والتحقق — نسخة التسليم

تاريخ إعداد التوثيق: 2026-10-10. المعايير المستخدمة من البند 7: التوسع والأمان والحالات الحدودية والمقايضات والأداء وتجربة المستخدم والصيانة وتبرير القرارات.

## القرارات والمقايضات

| القرار المنفذ | لماذا يلائم MVP | المقايضة والحد |
|---|---|---|
| Next.js واحد للواجهة والخادم | يقلل إعداد التشغيل ويوحّد العقود | التوسع بين عمليات يحتاج بنية إضافية، خصوصًا تحديد المعدل |
| قواعد حتمية أولًا، ونموذج اختياري | ترتيب الإجراء لا يتبدل بسبب صياغة نموذج | القواعد تحتاج كتابة وصيانة لكل نطاق مغطى |
| BM25 عربي محلي | شفاف وقليل التكاليف لمجموعة صغيرة، مع تطبيع ومرادفات | ليس embeddings؛ لا توجد مقارنة كمية شاملة على مجموعة أسئلة خارجية |
| Ollama محلي | لا مفتاح سحابي؛ الطلب للنموذج على الجهاز نفسه | تنزيل وذاكرة وتأخير CPU؛ تشغيل محلي لا يجعل كل بيانات الحساب مجهولة |
| Zod + ادعاءات مرتبطة بالمقاطع | يرفض JSON ومعرفات وروابط غير صالحة | تداخل الكلمات لا يثبت صحة المعنى أو حداثة المصدر بالكامل |
| MongoDB للحفظ | سجل واستجابة JSON، حسابات ودعم وقوائم في قاعدة واحدة | لا تشغيل حسابات دون القاعدة؛ مخطط العلاقات منطقي ويجب ضبطه بالتطبيق |
| upsert مع مفتاح طلب فريد | يمنع تضاعف سجل تدفق واحد حتى مع طلبين متزامنين | الاستدعاء المباشر دون UUID يجمع نفس النوع والنص؛ السجلات القديمة لا تُحذف تلقائيًا |
| جلسة مخزنة بالإضافة للتوقيع | إلغاء فوري عند الحظر وتغيير الدور والخروج | كل وصول محمي يحتاج تحقق قاعدة، وفشلها يمنع الدخول |
| فصل demo/production | لا تُقدّم مسودة على أنها معرفة معتمدة | production الآن بلا إجراءات معتمدة؛ جاهزية التطبيق تختلف عن اعتماد المحتوى |

## الأمان المنفذ

- scrypt بملح عشوائي، ومقارنة آمنة بدل حفظ كلمة المرور كنص.
- cookie من نوع HttpOnly وSameSite=Lax؛ Secure في production. الجلسة 8 ساعات، والتحقق يشمل الحساب والنسخة والانتهاء والسجل المخزن.
- التسجيل يمنح user من الخادم؛ وظائف المدير تتحقق من الدور وملكية البيانات على الخادم.
- الحظر والتعليق وتغيير الدور والخروج وإعادة كلمة المرور تبطل الوصول القديم. الحساب الرئيسي ونفس المدير وآخر مدير لهم قيود حماية.
- معرف تذكرة أو طلب لا يمنح الوصول بمفرده؛ يُتحقق من هوية صاحب السجل.
- تحديد المعدل محلي، ومدخلات محدودة ومتحقق منها. لا يوجد تدقيق اختراق مستقل، ولا مخزن معدل موزع، ولا نظام مراقبة إنتاجي مكتمل.

## الحالات الحدودية التي نعرضها

| الحالة | السلوك المطلوب في النسخة الحالية |
|---|---|
| «ساعدني» دون وصف كافٍ | سؤال توضيح بدل افتراض الملابس |
| «بدي أجدد هويتي» | خدمة خارج النطاق، ولا تتحول لمشروع |
| نشاط أو بلدية أو شكل قانوني مختلف | لا يستعير متطلبات رحلة الملابس |
| سؤال رسوم ومدد بلا دليل | insufficient_evidence، دون رقم مخترع |
| مقطع أو رابط مخترع في مخرج AI | رفض المخرج غير المتحقق |
| غياب Ollama | قواعد/استرجاع/خطة بديلة وحالة واضحة |
| غياب MongoDB | فشل دخول أو حفظ واضح، دون نجاح وهمي |
| سجل الطلب المكرر أو المتزامن | سجل واحد للمستخدم ومفتاح التدفق |
| تعديل الإيجار إلى ملكية | تبديل المستند والاحتفاظ بالعلامات المشتركة فقط |
| مستخدم محظور أو جلسة ألغيت | رفض الوصول القديم |
| هاتف صغير | نموذج تسجيل/دخول ضمن مساحة الشاشة في المقاسات المختبرة |

## أدلة التحقق وحدودها

- أعيد تشغيل Vitest عند إعداد التسليم: **154 اختبارًا ناجحًا في 24 ملفًا**، وtypecheck ناجح. لا تعني هذه الأرقام تقييم صحة كل جواب AI حي.
- lint وbuild يُتحقق منهما ضمن التحضير؛ النتيجة النهائية مسجلة في ملف `validation.json` داخل [مجلد العرض](presentation/).
- فحص حسابات حي سابق على النسخة الحالية: **39 تحققًا** على MongoDB وHTTP، باستخدام `scripts/verify-account-management.mjs`؛ يشمل إدارة الحسابات وإبطال الجلسات وسجل الطلب الواحد. يحتاج خادمًا وبيئة محلية وحساب مدير؛ ليس اختبارًا ينفذ بمجرد `npm test`.
- عند إعداد الوثائق فُحص أمر إنشاء البيئة كما هو في README: ولّد مفتاحًا عشوائيًا ولم يستبدل الملف الموجود. فُحص `db:setup` مرتين على قاعدة مؤقتة منفصلة: حساب عرض واحد بكلمة مرور مشتقة وفهرس انتهاء للجلسات. حُذفت القاعدة المؤقتة بعد الفحص؛ هذا ليس تشغيلًا كاملًا على جهاز ثانٍ.
- مراجعة المتصفح الموثقة: 32 عرضًا و8 تفاعلات، ثم 12 حالة للدخول و12 للتسجيل بمقاسات حتى 320×568 ونهاري/ليلي. اختبار التسجيل أرسل النموذج فعليًا بحساب مؤقت حُذف بعد التحقق. التفاصيل في [مراجعة UX](ux-review-2026-10-10.md) وملفات JSON في `docs/ux-review/`.
- [تقرير 2026-10-09](delivery-report.md) **تاريخي**؛ أرقام 81 اختبارًا وMongoDB اختياري أو غير مختبر تصف نسخة أقدم. لا تستخدمها كوصف للنسخة الحالية.
- فحص Ollama الحقيقي وقياسات CPU السابقة موجودة في التقرير التاريخي؛ لا نعرضها كـSLA أو قياس جديد على أجهزة اللجنة. أعد `ai:smoke` على الجهاز المستخدم إذا طلبت اللجنة دليل AI حيًا.

## أداء وتجربة مستخدم

تقلل القواعد والاسترجاع القصير عدد استدعاءات النموذج، وتعرض الواجهة انتظارًا وإلغاءً ونقص دليل. العربية RTL والمظهران وحفظ التفضيل والمصدر والدعم أجزاء منفذة. مراجعة WCAG/NN Group المذكورة في تقرير UX توجه التحسينات؛ ليست شهادة امتثال شاملة، ولا دراسة بشرية تقيس نجاح المهام.

## التوسع والجاهزية

يمكن مراجعة مصادر جديدة وإضافة قواعد واختبارها دون تغيير فكرة المشروع. عند الحاجة لتشغيل موزع يجب قياس الحمل ونقل محدد المعدل إلى مخزن مشترك وتحسين فهارس الاستعلامات وربط البريد ومراجعة الأمان. هذه متطلبات لاحقة وليست ميزات منجزة. يركز العرض على MVP كما يطلب البند 8.
