# قائمة تسليم المشروع

وفق رسالة المنظمين: ارفعوا الكود على GitHub، ثم قدّموا رابط المستودع على موقع التسليم، وسلّموا العرض. موعد فتح التسليم المنقول هو 11:30؛ لا يُفترض منه موعد إغلاق غير معلن.

## قبل رفع المستودع

- [ ] اسم المستودع واضح، والكود الكامل موجود مع `package.json` و`package-lock.json`.
- [ ] `README.md` ظاهر في جذر المستودع، وكل روابط `docs/` تعمل.
- [ ] `.env.example` موجود؛ `.env.local` وأسرار Atlas وكلمات مرور المدير مستبعدة.
- [ ] لا ترفع `node_modules/` أو `.next/` أو `.local-data/` أو بيانات حسابات المستخدمين أو ZIP داخل المستودع.
- [ ] راجع الملفات المضافة قبل commit؛ لا ترفع ملفات خاصة من جهاز الفريق.
- [ ] جرّب `npm ci` والإعداد و`db:setup` والديمو على قاعدة جديدة تخص التجربة.
- [ ] اختبر أن أعضاء اللجنة يستطيعون تنزيل المستودع؛ إن كان خاصًا امنح الوصول حسب تعليماتهم.

## ملفات العرض

- [ ] سلّم [Mustanad-Jo-Final.pptx](presentation/Mustanad-Jo-Final.pptx) أو [Mustanad-Jo-Final.pdf](presentation/Mustanad-Jo-Final.pdf) حسب صيغة منصة التسليم؛ هذه النسخة تضيف نقاط القوة وخارطة التطوير، وملاحظات وقتها في speaker-notes.md.
- [ ] راجع الأسماء الحقيقية ومدة العرض؛ لا توجد أسماء فريق مفترضة في الملفات.
- [ ] تدربوا على [ملاحظات العرض](presentation/speaker-notes.md) والديمو والأسئلة.
- [ ] قدموا معايير الصور وأوزانها باستخدام فكرة Mustanad Jo؛ توثيق PDF السابق مرجع مستقل، ولا تغيّروا فكرة المشروع إلى موضوعه.
- [ ] اختبروا نسخة العرض بعد تنزيلها من GitHub، وليس النسخة المحلية فقط.

## عند التسليم

- [ ] انسخ رابط المستودع الفعلي إلى منصة المنظمين.
- [ ] ارفع العرض المطلوب وتأكد من ظهور الملفات.
- [ ] احتفظ برقم commit المستخدم للتسليم، ولا تدّعِ نشرًا أو قبولًا قبل حدوثه.

التحضير المحلي للملفات لا ينشر المستودع أو يرسل التسليم تلقائيًا.
