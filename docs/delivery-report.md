# تقرير التسليم المختصر

> تقرير تاريخي لنسخة 2026-10-09. أرقام الاختبارات ووصف MongoDB هنا لا يصفان النسخة الحالية. مرجع التسليم الحالي: [README](../README.md) و[المراجعة الهندسية](engineering-review.md).

تاريخ الفحص: 2026-10-09

## البيئة

- الجهاز: ASUS Vivobook X1504ZA.
- الذاكرة: 7.69GB RAM؛ كانت الذاكرة الحرة عند الفحص الأول 0.63GB.
- الرسوميات: Intel UHD مدمجة، ذاكرة معروضة 1GB، ولا توجد بطاقة NVIDIA.
- القرص C: مساحة حرة 314.5GB وقت الفحص.
- Node.js: 22.19.0.
- النموذج المختبر: `qwen3:1.7b` (حزمة Ollama نحو 1.4GB)، مع سياق 4096 لتقليل ضغط الذاكرة.
- Ollama: الإصدار 0.40.1، يعمل على المعالج لأن Intel UHD المدمجة لم تُستخدم للتسريع، والمنفذ مقيد بـ`127.0.0.1:11434`.

## ما تم تنفيذه

- Next.js + TypeScript + Tailwind في تطبيق واحد، مع App Router وRoute Handlers.
- بداية، wizard سؤال واحد كل مرة، رحلة، قائمة تجهيز، تعديل حالة، سجل مصادر، ومساعد أسئلة.
- محرك قواعد قابل للتدقيق، نتيجة `unknown` مستقلة، ترتيب طوبولوجي، ورفض الدورات والمراجع المفقودة.
- فصل `data/procedures.json` المعتمد (فارغ حتى المراجعة البشرية) عن `data/demo-procedures.json` الموسوم تجريبيًا.
- RAG نصي عربي محلي، Structured JSON، Zod، إصلاح واحد، والتحقق من أن كل استشهاد ضمن المقاطع المسترجعة.
- موائم Ollama خلف الخادم فقط، localhost فقط، ومهلة/سياق/حد إخراج قابلة للتهيئة.
- fallback كامل عند غياب Ollama أو النموذج، دون إجابات AI محفوظة أو وهمية.
- حاجز نية يمنع طلبات المعاملات الشخصية مثل «أجدد هويتي» من الوصول إلى رحلة الملابس أو مولّد الاستكشاف.
- دخول محلي بجلسة موقعة، وصفحة سجل، وتكامل MongoDB اختياري لتخزين الردود السابقة لكل مستخدم.

## نتائج التحقق البرمجي

- `npm.cmd run typecheck`: ناجح.
- `npm.cmd run lint`: ناجح.
- `npm.cmd test`: ناجح — 81/81 اختبارًا في 10 ملفات.
- `npm.cmd run build`: ناجح — جميع صفحات وواجهات API بُنيت.
- HTTP smoke: الصفحة الرئيسية 200؛ intake طلب الشكل القانوني الناقص؛ رحلة الإيجار أعادت 3 خطوات ومستندي تجهيز؛ سؤال حقن غير مرتبط أعاد `insufficient_evidence` ولم يستدعِ AI.
- HTTP إنتاجي بعد البناء: `/api/status` أعاد `available=true` و`model=qwen3:1.7b`، و`/api/answer` أعاد `answered` و`aiMode=ollama` مع الاستشهاد `gam-tenure-documents`.
- مراجعة Edge: صفحة الدخول والرئيسية ورسالة الخدمة غير المدعومة والرحلة والاستكشاف والمصادر على الهاتف والحاسوب. لم يظهر تمرير أفقي؛ سجّل الفحص `scrollWidth` مساويًا للـviewport في جميع اللقطات.
- HTTP حي: تسجيل الدخول نجح؛ «بدي أجدد هويتي» أعاد `unsupported_service` بالقواعد مع 3 خدمات مدعومة ولم يستدعِ AI؛ الحلويات بقيت `business_journey/unsupported_activity` والملابس بقيت `business_journey/covered_demo`.
- MongoDB غير مثبت على جهاز التسليم؛ التكامل بُني ونجح فحص fallback (`configured=false/available=false`) لكن لم يُختبر insert حي حتى تشغيل MongoDB محليًا وضبط `MONGODB_URI`.

## تدقيق ما بعد النسخة الأولى

- أُصلح دمج intake حتى لا تمحو قيم `null` القادمة من Ollama حقولًا صحيحة، مع أولوية نهائية لاختيار المستخدم.
- أُضيفت عقود واجهة مشتركة وعميل HTTP موحد، وإلغاء للطلبات القديمة لمنع سباقات الحالة.
- أُصلح عداد تقدم الأسئلة، ومسار فتح `/journey` دون معاملات، وأخطاء تحميل سجل المصادر، وفشل حفظ Local Storage.
- أصبحت استشهادات جواب AI قابلة للفتح والقراءة، وأضيفت أسئلة مقترحة ورسائل انتظار واقعية.
- فُصل إدخال الهدف عن سؤال المعرفة، مع كشف تلقائي للأسئلة؛ لم يعد السؤال الحر يُجبر على رحلة الملابس.
- تحسن وصف الرحلة الكامل من 16.6ث إلى نحو 0.3ث في فحص dev لأنه يُحسم بالقواعد دون استدعاء Ollama. بقيت إجابة RAG الحية أبطأ بطبيعتها (45.7ث في آخر فحص CPU).
- أزيلت المطابقة الكاذبة الناتجة عن كلمات السؤال العربية القصيرة؛ سؤال «ما عاصمة فرنسا؟» أعاد `insufficient_evidence` و`aiMode=not_called` بلا استشهادات.
- أضيف حاجز نطاق قبل RAG: السؤال عن مطعم أو شركة أو مدينة مختلفة، وحتى هدف جديد غير معروف مثل مغسلة داخل رحلة الملابس، لا يستدعي Ollama ولا يعيد استشهادات الملابس.
- أضيف `/explore` للحالات غير الموجودة في القواعد. مثال «بدي أفتح محل حلويات بخلدا» استُخرج حيًا كـ`food/physical` في خلدا وبُنيت له 5 مراحل: تثبيت الوصف، التصنيف والتسجيل، الموقع، ضوابط الغذاء، وقائمة التنفيذ الموثقة.
- أُضيف مستند هندسة يوضح التدفق وحدود الوحدات وثوابت السلامة وطريقة إضافة رحلات جديدة.
- أضيفت واجهة دخول محلية مستوحاة من بساطة تطبيقات الخدمات الأردنية مع تنبيه صريح أنها ليست سند، وصفحة سجل لا تدّعي وجود MongoDB عند انقطاعه.
- اختبار مستخدم عشوائي كشف أن «محل ألعاب» قد يتحول إلى ملابس وأن «ساعدني» قد يدفع النموذج لاختراع رحلة؛ أُغلقت الحالتان بقواعد نية وحقول حتمية واختبارات regression.
- أضيفت صيغ يومية مثل تجديد الهوية والجواز، حجز موعد، دفع فاتورة، كشك قهوة، مغسلة، تطبيق توصيل والاستفسار الحر.
- انخفض intake الواضح إلى نحو 19–59ms بعد الطلب الأول، وخطط الاستكشاف الشائعة إلى نحو 35–46ms بدل 5–10 ثوانٍ. انخفض RAG الحي من 63.9ث مع التفكير إلى 13.1ث دونه، مع بقاء جواب `answered` واستشهاد صالح.
- أُعيد بناء RAG العربي باستخدام BM25 موزون وتطبيع صرفي خفيف ومرادفات ومطابقة خطأ إملائي واحد. اختُبرت استعادة المقاطع الستة بصيغ مختلفة مع رفض «ما عاصمة فرنسا؟» وprompt injection.
- كشف الاختبار الحي أن النموذج يستطيع اختلاق رابط مع الاستشهاد بمعرف صحيح؛ أضيف تحقق نصي للادعاء وحظر URL غير الموجود، وأصبح الجواب المنشور مبنيًا من claims المتحققة فقط.
- وضع RAG الهجين أعاد «عقد الاجيار المصدق» خلال 247ms و«دليل تسجيل الاسم التجاري» خلال 39ms كإجابة extractive موثقة؛ السؤال التفسيري الكامل استخدم Ollama خلال نحو 11.4ث.
- `npm audit` أبلغ عن 5 إدخالات مترابطة في سلسلة lint التطويرية (`eslint-config-next -> fast-glob -> micromatch -> braces`). اقتراح npm هو downgrade رئيسي غير متوافق إلى Next 14؛ لذلك لم يُطبق إصلاح قسري. لا تقع هذه السلسلة ضمن تبعيات تشغيل الموقع.

## حالة المحتوى الرسمي

- جُمعت 4 صفحات/بطاقات رسمية و6 مقاطع داعمة من وزارة الصناعة والتجارة وأمانة عمّان.
- جميعها `pending` وليست `reviewed` بشريًا. وضع الإنتاج يستبعدها بالكامل ويعلن نقص المعرفة بدل نشر رحلة فارغة كأنها معتمدة.
- التفرع الإيجار/الملكية مدعوم بنص رسمي قديم، لكنه يحتاج بطاقة حديثة تثبت انطباقه على محل ملابس تجاري.
- لم يثبت تصنيف نشاط بيع الملابس أو المتطلبات التفصيلية الحديثة لرخصة المهن؛ لم تُضف أي رسوم أو مدد.

## حالة AI الحي

- اختُبر اتصال حقيقي مع Ollama المحلي، وليس mock: ناجح.
- استخراج الحقول العربي: JSON صالح في التشغيل البارد والدافئ؛ 8.27ث ثم 5.67ث.
- سؤال RAG عن وثيقة المحل المستأجر: `answered` بعد التحسين خلال نحو 13.1ث، بإجابة واستشهاد ضمن المقاطع المسترجعة فقط.
- المقاطع الأربعة المسترجعة شملت مقطع تفرع الإيجار/الملكية أولًا، واجتاز الناتج Zod وفحص معرّفات الأدلة.
- أوصى فحص الأداء بـ62 ثانية؛ ضُبطت `AI_TIMEOUT_MS=65000` كهامش عملي لهذا الجهاز.
- المسار غير المعتمد أو الدليل غير الكافي يعيدان `insufficient_evidence`، وتعطل Ollama يعيد الواجهة إلى وضع القواعد دون اختلاق إجابة.
