# Mustanad Jo

مساعد عربي لأصحاب المشاريع يحوّل وصف الفكرة إلى خطوات مفهومة، خطة تشغيل، قائمة تجهيز، وإجابات مرتبطة بمصادر. يستطيع المستخدم متابعة طلباته والتقدّم وإرسال مشكلة للدعم، ويستطيع المدير إدارة الحسابات والدعم من لوحة مستقلة.

هذا **MVP إرشادي**. خطط الأعمال العامة تختلف عن الإجراءات الحكومية: رحلة الإجراءات التجريبية محدودة بمحل ملابس في عمّان، مؤسسة فردية، مستأجر أو مملوك. المحتوى الرسمي الحالي بانتظار مراجعة بشرية؛ التطبيق لا يمنح موافقات ولا يخمّن رسومًا أو مددًا.

## المتطلبات

| المتطلب | الاستخدام |
|---|---|
| Node.js **22.12+ ضمن إصدار 22، أو 24.x** | تشغيل التطبيق وأدوات الاختبار؛ لا يكفي متطلب Next.js وحده |
| npm و`package-lock.json` المرفق | تثبيت الإصدارات باستخدام `npm ci` |
| MongoDB | إلزامي للحسابات والجلسات والسجل والقوائم والدعم؛ محلي أو Atlas |
| Docker مع محرك يعمل، أو MongoDB مثبت | اختر طريقة واحدة لتشغيل القاعدة |
| Ollama + `qwen3:1.7b` | اختياري لتجربة AI المحلي الفعلي |
| إنترنت عند الإعداد | لتنزيل الحزم وصورة القاعدة والنموذج إن استُخدم |

التقنيات: Next.js، React، TypeScript، Tailwind، MongoDB، Zod. الإصدارات الدقيقة في [package.json](package.json) والـlockfile. لا يحتاج مفتاح API مدفوعًا. المنافذ الافتراضية: الموقع `3000`، MongoDB `27017`، Ollama `11434`. الموقع يستمع إلى `127.0.0.1`.

## التشغيل على جهاز اللجنة — Windows PowerShell

نزّل المستودع أو فك ZIP، وافتح الطرفية داخل المجلد الذي يحتوي `package.json`. لا تحتاج ملفات من جهاز المطوّر.

### 1. تشغيل MongoDB

إذا كانت خدمة MongoDB المحلية تعمل، انتقل للخطوة التالية. بديل Docker:

```powershell
docker run --name lifeevent-mongo -p 127.0.0.1:27017:27017 -v lifeevent-mongo-data:/data/db -d mongo:8
```

لاحقًا استخدم `docker start lifeevent-mongo`. الـvolume يحافظ على البيانات. يمكن استخدام Atlas بتعديل `MONGODB_URI`.

### 2. تثبيت الحزم وإعداد البيئة

```powershell
node --version
npm.cmd ci
```

أنشئ `.env.local` **مرة واحدة** وولّد مفتاح جلسة عشوائيًا. الأمر لا يستبدل ملفًا موجودًا:

```powershell
node -e "const fs=require('node:fs'); if(!fs.existsSync('.env.local')) { const secret=require('node:crypto').randomBytes(32).toString('hex'); fs.writeFileSync('.env.local',fs.readFileSync('.env.example','utf8').replace(/^AUTH_SECRET=.*$/m,'AUTH_SECRET='+secret)); console.log('Created .env.local'); } else console.log('.env.local already exists; retained');"
```

للبداية السريعة دون تنزيل النموذج، عدّل `AI_ENABLED=false` في `.env.local`. **MongoDB يبقى مطلوبًا** دون AI. أبقِ `KNOWLEDGE_MODE=demo` لعرض المحتوى الحالي. لا ترفع `.env.local` إلى GitHub.

### 3. حساب العرض وتشغيل الموقع

```powershell
npm.cmd run db:setup
npm.cmd run dev
```

افتح **http://127.0.0.1:3000**، وسجّل الدخول:

| المستخدم | كلمة المرور |
|---|---|
| `demo` | `demo1234` |

هذه بيانات عرض محلي وليست حساب صاحب المشروع. يمكن تغيير `DEMO_USERNAME` و`DEMO_PASSWORD` قبل أول تهيئة؛ `db:setup` لا يغيّر كلمة مرور حساب موجود. إنشاء حساب جديد متاح بالاسم والبريد والهاتف وكلمة المرور. دخول المستخدم العادي يفتح الرئيسية؛ المدير يفتح لوحة الإدارة.

### 4. حساب المدير

حدّد `ADMIN_USERNAME` و`ADMIN_EMAIL` في `.env.local` وضع كلمة مرور تختارها من **12 حرفًا على الأقل** في `ADMIN_PASSWORD`، ثم:

```powershell
npm.cmd run db:admin
```

ادخل باسم المدير أو بريده وكلمة المرور التي حددتها. اللوحة على `/admin`. الحساب الرئيسي محمي. الأمر لا يعيد ضبط كلمة مرور مدير موجود؛ لا توجد كلمة مرور مدير حقيقية في التسليم.

### 5. AI المحلي — اختياري

ثبّت Ollama ثم:

```powershell
ollama pull qwen3:1.7b
ollama list
```

شغّل `ollama serve` في طرفية منفصلة إن لم تعمل الخدمة تلقائيًا. ضع `AI_ENABLED=true` وأعد تشغيل Next.js. النموذج يُنزّل منفصلًا ويحتاج ذاكرة ومساحة إضافيتين؛ الأداء يعتمد على الجهاز. موائم المشروع يقبل عنوان Ollama محليًا فقط.

فحص الاتصال: `/api/status`. فحص النموذج الحقيقي: `npm.cmd run ai:smoke`. عند غياب Ollama تستمر القواعد والاسترجاع والخطط البديلة وتظهر حالتها؛ نجاح الوضع البديل لا يعني تشغيل نموذج AI.

## macOS / Linux

نفس خطوات MongoDB وOllama، مع `npm` بدل `npm.cmd`. أمر إنشاء البيئة أعلاه يعمل في Bash أيضًا:

```bash
npm ci
# نفّذ أمر node لإنشاء البيئة أعلاه، واضبط الاتصال وAI_ENABLED
npm run db:setup
npm run dev
```

تم التحقق الفعلي على Windows. أوامر الأنظمة الأخرى موثقة ولم تُختبر على جهاز منفصل. أداة لقطات Edge الخاصة بـWindows ليست متطلب تشغيل الموقع.

## النسخة المبنية

بعد إعداد البيئة والقاعدة والحسابات:

```powershell
npm.cmd run build
npm.cmd run start
```

أوقف `dev` قبل `start` على نفس المنفذ. لتغييره: `npm.cmd run dev -- -p 3001` أو `npm.cmd run start -- -p 3001`. استعادة كلمة المرور تعرض رابطًا محليًا في `dev` فقط؛ إرسال البريد غير موصول، ولا يظهر رابط استعادة في الإنتاج.

## الديمو

1. ادخل بـ`demo`؛ الرئيسية نقطة البداية.
2. اكتب **بدي أفتح محل ملابس بعمان**. اختر مؤسسة فردية ومحلًا مستأجرًا عند طلب التوضيح.
3. افتح الرحلة، وراجع ترتيب الخطوات والمستندات والمصدر وحالة «بانتظار مراجعة بشرية».
4. علّم مستندًا وأعد تحميل الصفحة للتحقق من حفظ التقدّم. النسبة تعني تجهيز المستخدم، وليست موافقة حكومية.
5. غيّر الحالة إلى مملوك؛ لاحظ اختلاف مستند الموقع والاحتفاظ بالعلامات المشتركة.
6. اسأل **عقد الاجيار المصدق** ثم **كم الرسوم وكم تستغرق؟**. تظهر الأدلة أو نقصها دون اختراع أرقام.
7. ابدأ **بدي أفتح مغسلة سيارات بعمان**؛ لاحظ خطة المجال المختلفة، مع الفصل بين التخطيط العام والمتطلبات الرسمية.
8. افتح السجل: التدفق الجديد يُحفظ مرة واحدة ويُحدّث أثناء إكماله؛ قراءته لا تولّد طلبًا. بدء طلب مستقل يولّد سجلًا جديدًا حتى إن تكرر النص.
9. افتح الملف الشخصي والدعم وأرسل رسالة تجريبية. ادخل بالمدير لعرض الرد وإدارة الحسابات؛ استخدم حسابًا مستقلًا للحظر أو الحذف.

توقيت العرض المقترح في [ملاحظات المتحدث](docs/presentation/speaker-notes.md). يمكن عرض PDF واللقطات عند تعذّر الديمو مع التصريح بأنها صور وليست تشغيلًا حيًا.

## إعدادات البيئة

المرجع الكامل [.env.example](.env.example). الإعدادات على الخادم:

| الإعداد | الغرض |
|---|---|
| `MONGODB_URI`, `MONGODB_DB_NAME`, `MONGODB_CONNECT_TIMEOUT_MS` | اتصال القاعدة، الاسم الافتراضي `lifeevent_ai`، مهلة الاتصال |
| `AUTH_SECRET` | مفتاح عشوائي لتوقيع الجلسات، مستقل لكل جهاز |
| `DEMO_USERNAME`, `DEMO_PASSWORD` | إنشاء حساب العرض أول مرة |
| `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | إنشاء المدير محليًا |
| `AI_PROVIDER`, `AI_ENABLED` | المزود الحالي Ollama وتفعيل النموذج |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_NUM_CTX` | العنوان المحلي والنموذج والسياق الافتراضي 4096 |
| `AI_TIMEOUT_MS`, `AI_RETRY_COUNT` | مهلة افتراضية 65000ms وإعادة محاولة |
| `AI_MAX_OUTPUT_TOKENS`, `AI_ANSWER_MAX_OUTPUT_TOKENS`, `AI_ANSWER_THINK` | حدود الإخراج؛ التفكير معطّل افتراضيًا |
| `RAG_RESPONSE_MODE` | `hybrid`: اقتباس سريع للحالات الواضحة ونموذج للأسئلة التفسيرية |
| `INTENT_AI_ENABLED`, `INTAKE_SLOT_AI_ENABLED` | معطّلان افتراضيًا؛ القواعد والاختيارات أولًا |
| `EXPLORATION_AI_MODE` | `smart`: النموذج عند الغموض |
| `KNOWLEDGE_MODE` | `demo` للعرض؛ `production` يستبعد غير المراجع، وقواعده حاليًا فارغة |
| `RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW_MS` | تحديد معدل داخل ذاكرة العملية فقط |

```text

lib/            قواعد المجال، الاسترجاع، الحسابات، الحفظ والعقود
lib/ai/         موائم Ollama والتحقق من مخرجاته
data/           المصادر والمقاطع وقواعد demo/production
scripts/        تهيئة الحسابات وفحوص AI والحسابات والمتصفح
```

الفصل منطقي داخل تطبيق Next.js واحد. [تصميم النظام](docs/system-design.md) يحتوي مخطط البنية وMongoDB وكل API. [الهندسة](docs/architecture.md) تشرح القواعد وتوسيعها. مراجع الوحدات: [الحسابات](docs/accounts.md)، [الإدارة](docs/admin.md)، [الملف والدعم](docs/profile-support.md)، [السجل](docs/request-history.md).

## التحقق وحل المشاكل

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
```

Vitest لا يحتاج نموذجًا حيًا. فحوص التكامل تحتاج MongoDB وخادمًا وحساب إدارة. [تقرير التحقق](docs/engineering-review.md) يوضح الأدلة وحدودها.

| المشكلة | الحل |
|---|---|
| `npm.ps1` محظور | استخدم `npm.cmd` |
| `ECONNREFUSED` أو تعذّر الدخول والحفظ | شغّل MongoDB وتحقق من `MONGODB_URI` ثم `db:setup` |
| `--env-file` أو خطأ إصدار Node | استخدم إصدار Node المطلوب أعلاه |
| demo لا يدخل | هيّئ نفس القاعدة؛ الحساب الموجود لا تُعاد كتابة كلمة مروره |
| اسم حاوية Docker مستخدم | `docker start lifeevent-mongo` |
| المنفذ مشغول | أوقف خادمك السابق أو استخدم `-p 3001` |
| النموذج غير مثبت | `ollama pull qwen3:1.7b` وتحقق من `AI_ENABLED` ثم أعد التشغيل |
| جواب AI بطيء | الأداء يعتمد على CPU والذاكرة؛ عاير بـ`ai:smoke` أو استخدم الوضع البديل |
| لا تظهر إجراءات في `production` | متوقع؛ لا توجد إجراءات اجتازت المراجعة، استخدم `demo` للعرض |
| الاستعادة لا ترسل بريدًا | البريد غير موصول؛ الرابط المحلي في `dev` فقط |

## الافتراضات والحدود

العرض يستهدف عملية واحدة. MongoDB إلزامي؛ تعذّر التحقق من جلسة يمنع الوصول. تعطل Ollama له بديل، أما تعطل القاعدة فلا يُقدّم كنجاح حفظ. الحسابات تجمع الاسم والبريد والهاتف بشكل مقصود؛ حجب بعض الأرقام في نص الطلب ليس إخفاءً شاملًا للبيانات الشخصية.

لا يوجد دفع أو رفع وثائق أو تكامل حكومي أو بريد دعم/استعادة موصول. لوحة الإدارة موجودة وتقرأ بيانات القاعدة الفعلية. لا توجد شهادة أمن أو وصول شامل أو اختبار حمل موزع أو قياس بشري لنجاح المستخدم. القرارات والمقايضات في [المراجعة الهندسية](docs/engineering-review.md).

لا تُرفق `.env.local` أو قاعدة بيانات صاحب المشروع أو `node_modules` أو `.next` مع التسليم. المطلوب هو الكود والـlockfile ومثال البيئة والتوثيق والعرض؛ اتبع [قائمة التسليم](docs/submission-checklist.md).
